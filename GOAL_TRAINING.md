# Online milestones and goal-conditioned A2C

Enable the companion pipeline alongside R2-Dreamer:

```bash
conda activate r2dreamer
bash runs/atari_goals.sh logdir=logdir/my_goal_experiment
```

The launcher uses H.E.R.O., seed 0, the 100M R2-Dreamer configuration,
and 400,000 emulator-frame units: 100,000 decisions with action repeat 4 and
the default single Dreamer environment. Goal-policy interactions are separate
and do not enter that budget, Dreamer's replay, or the classifier's corpus.
The feature is disabled for ordinary `train.py` runs.

The implementation interleaves the learners synchronously. Dreamer pauses
while a companion batch runs; it does not need a second GPU. Companion work
preserves Dreamer's Python, NumPy, and Torch random-number streams. The agents
share neither trainable parameters nor optimizers. This adds wall-clock cost,
not Dreamer exploration steps.

## Data and classifier versions

Only complete **training** trajectories generated by R2-Dreamer enter the
recent trajectory buffer; periodic Dreamer evaluation trajectories are excluded.
Each stored trajectory includes the reset image through the final observation,
its episode ID, completion step, and environment return. Rewards are metadata,
not classifier labels. The final unfinished trajectory is discarded.

The default classifier starts from scratch. It uses the previous skip-gram
sampling: within-episode neighbors within five observations are positives;
random frames are negatives, rejecting same-episode pairs within that window.
By default it gets 200 warm-up updates after two completed episodes, then 20
updates every two new completed episodes, using the latest 32 episodes.

After those updates, the manager makes an independent frozen classifier copy.
That **exact same copy**, including any BatchNorm state, both extracts anchors
and computes rewards throughout a whole goal batch, across all recurrent
optimization chunks. Neither its weights nor statistics change. The live
classifier can update only between batches. Batch logs record the classifier
version and source episode IDs.

Anchor extraction preserves the original first-different-frame rule and the
0.5 decision threshold. The initial frame is omitted from reward-bearing goals.
There is no forced final anchor and no fixed-spacing subsampling. An empty
goal list is reported as skipped, never counted as success.

R2-Dreamer's normal observations are RGB 64×64. The online pipeline resizes
those observations to RGB 84×84, using the same conversion in the goal-agent
environments. It does not change Dreamer's visual input. An optional warm start
from a classifier trained on the same game is available. The H.E.R.O. experiment
starts from scratch; it does not reuse the earlier Montezuma classifier:

```bash
bash runs/atari_goals.sh \
  goal_conditioning.classifier.checkpoint=/path/to/hero_classifier.pt \
  logdir=logdir/my_warm_started_experiment
```

## Variable lengths and attention

The goal batch contains up to four trajectory-derived sequences of different
lengths. Images are padded on CPU, but padding never enters the visual encoder
or the anchor GRU. `pack_padded_sequence` / `pad_packed_sequence` provide one
contextual GRU output per real anchor, in the original sequence order.
Long image sequences use chunked encoding and activation checkpointing.

At every environment step, the controller receives the current visual feature,
its previous GRU hidden state, the explicitly indexed **next-anchor** embedding,
and progress features. Its new hidden state queries cross-attention over the
anchor GRU outputs. The actor and critic use that attention context along with
the recurrent state and current goal. Explicitly supplying the next anchor
prevents attention alone from having to infer which goal earns the next reward.

Padding is always masked. Completed anchors are masked by default, leaving the
current and future anchors visible. This is a design choice, not a requirement:
the controller retains its recurrent history, and future anchor GRU outputs
already carry context from preceding anchors. To compare keeping completed
anchors visible, use:

```bash
bash runs/atari_goals.sh goal_conditioning.policy.mask_completed=False
```

Progress and the next-anchor input remain present in either variant. Empty or
fully completed rows have a safe dummy attention key and zero goal context;
fully masked softmax rows cannot produce NaNs.

## Fresh rollouts and A2C

R2-Dreamer trajectories specify goals; their actions are **not** used as A2C
training samples. Each nonempty goal sequence gets a fresh independent Atari
environment with the same game/action/preprocessing configuration and its own
seed. Resets use the usual environment initialization, including configured
random no-ops; emulator states from the source trajectories are not restored.

The goal policy samples its own actions. After a transition, the frozen
classifier compares the new observation only to the next unachieved anchor.
A match earns exactly +1 and advances the cursor once. Looking like a later
anchor earns nothing until preceding anchors have been achieved. A single
transition cannot claim several anchors. Atari score is logged separately and
does not contribute to the A2C loss.

The default learner uses 32-step n-step A2C updates, gamma 0.99, a value loss,
and an entropy bonus. The anchor encoder/GRU, controller, attention, actor, and
critic train jointly. Controller hidden states are carried forward but detached
at optimization boundaries. Anchor embeddings are recomputed after each update
so gradients reach the anchor GRU without reusing stale computation graphs.

Each trajectory has its own valid-step mask. Actual terminal states and
completion of all goals stop bootstrapping; time limits bootstrap from the
final observation rather than a reset image. Default training attempts are
capped at 4,096 decisions; final evaluation allows 27,000. These are configurable:

```bash
bash runs/atari_goals.sh \
  goal_conditioning.policy.max_steps=27000 \
  goal_conditioning.policy.rollout_steps=64
```

## Final evaluation and saved files

After Dreamer finishes, its checkpoint is saved first. The companion then
freezes both learned models and attempts up to five **latest completed** source
trajectories whose completion steps lie in the final 20% of Dreamer's budget.
It uses new evaluation seeds, greedy actions by default, and no optimizer
updates. It never fills missing slots with older or partial trajectories. The
recency window and requested count are configurable under
`goal_conditioning.evaluation`. These are evaluations of executing recently
generated goals, not an independent held-out-goal benchmark.

Under `<logdir>/goal_conditioning/`:

- `classifier.pt`: online classifier, version, training settings and optimizer.
- `goal_agent.pt`: goal policy, optimizer, update counts and classifier version.
- `recent_trajectories/`: bounded recent RGB trajectory NPZs and manifest.
- `metrics.jsonl`: per-batch source IDs, classifier versions, anchor indices,
  A2C losses, ordered completion statistics, and separate interaction counts.
- `evaluation.json`: latest-source eligibility, full-sequence success rate,
  achieved-prefix fraction, per-goal hit steps, empty-sequence counts and steps.
- `evaluation/source_XXXXXX/`: source and goal-policy MP4s, anchor PNGs, a
  contact sheet, and the per-trajectory result.

`env_steps` in companion metrics counts goal-policy decisions; with action
repeat 4, multiplying by four gives the nominal emulator-frame budget units.
Dreamer's `dreamer_step` already uses those frame units. Use a fresh logdir for
each run; joint resume is not implemented. Existing goal artifacts are rejected
to avoid mixing old trajectories with newly initialized learners.

## Relation to HER and limitations

Choosing goals from achieved trajectories is a hindsight goal-construction
strategy. Variable sequence length itself does not make it HER. Conventional
[Hindsight Experience Replay](https://arxiv.org/abs/1707.01495) also relabels
goals/rewards on stored transitions and trains an off-policy learner on them.
Directly applying ordinary A2C to Dreamer's actions or to goal-relabeled old
actions would violate its on-policy assumption. This baseline therefore uses
fresh goal-policy rollouts and does not perform HER replay.

A later multi-goal HER variant could relabel an ordered suffix or subsequence
of goals actually reached by the goal policy, reconstruct the progress cursor
and rewards, and train an off-policy recurrent learner with appropriate
sequence context. That is a separate algorithmic extension.

The classifier measures learned temporal similarity, not semantic achievement.
Repeated states, flicker, shared prefixes, and classifier drift between batches
can affect rewards. Sparse long-goal tasks may remain difficult for plain A2C.
Inspect videos, zero-anchor frequency, goal counts and achieved-prefix curves
alongside success rates; high classifier-based completion alone does not prove
meaningful navigation skill. Useful future comparisons include a fixed
classifier and a short-prefix curriculum, but neither changes this baseline.
